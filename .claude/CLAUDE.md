# グローバル作業規約

- ユーザーへの回答・報告は日本語で書く。

## ユーザー指定の除外対象

- ユーザーが除外を指定したプロジェクトと関連する過去ログ・memoryを読まず、検索せず、参照せず、外部へ送信しない。作業に必要なら停止してユーザーに確認する。

## 共通の作業規約

- 変更前に、対象アプリケーション、Git リポジトリ、作業ディレクトリ、既存状態を実データで確認する。名称が曖昧で結果が変わる場合だけ、変更せず質問する。
- 恒久的な作業規約はこのファイルまたはリポジトリ管理された文書に置く。Memory と会話履歴は補助情報であり、規約の正本にしない。
- 変更・実装では、対象リポジトリの `CLAUDE.md` / `AGENTS.md`、検証コマンド、Git 状態を確認し、未検証の結果を完了と報告しない。
- 別 task の変更やユーザー所有の未追跡ファイルを、明示指示なしに編集、移動、削除しない。
- Bash では `cd X && ...` / `cd X; ...` を使わず、絶対パスや `git -C <path>`、`uv run --directory <path>` で対象を指定する（`cd` を含む複合コマンドは承認確認が出るため）。

## セッションの引き継ぎ

- セッションのコンテキスト使用量が 50% を超えたら、新しい作業単位を始めず、進行中の操作を安全な区切りまで終えてから `/session-handoff` で handoff を保存し、次のセッションへ移る。
- 自分では新しいセッションを開けないので、最後に handoff の path と、貼り付けて使う再開プロンプトをユーザーに渡す。
- 使用量が正確に分からないときは、長い調査・実行・多数のファイル読み込みを重ねた時点で 50% 超とみなし、早めに引き継ぐ。

## 複数 Issue の連続実行（オーケストレーター方式）

- 2 件以上の Issue を連続して頼まれたら、メインセッションは指揮役に徹し、Issue 1 件ごとに新しいサブエージェント（Agent tool）を起動して実装させる。メインで直接実装しない。
- 実装を担当するサブエージェントには `model: "opus"` を指定する（既定のサブエージェントモデルは sonnet）。単純な検索・確認だけの補助は既定モデルのままでよい。
- サブエージェントへの依頼には、リポジトリの path、Issue 番号、使う skill（例：`/issue-development-workflow`）、完了条件（検証済み・PR 作成まで等）、前の Issue から引き継ぐ事実を書き、会話履歴なしで着手できるようにする。
- サブエージェントには、結果を短い要約（PR URL、検証結果、未解決事項、次の Issue に影響する変更）で返させる。メインはファイル本文やログを読み込まず、要約だけを保持する。
- 依存関係のある Issue は順番に実行し、独立した Issue は worktree を分けて並列化してよい（`isolation: "worktree"`）。
- サブエージェントが失敗・ブロックした場合は、その Issue で止めてユーザーに報告する。推測で次へ進めない。
- 全件が終わったら、Issue ごとの結果一覧を報告する。メインのコンテキストが 50% を超えたら、上記「セッションの引き継ぎ」に従う。

## Codex と共有する skill

- `~/.claude/skills` の skill は Codex と同じ source を共有する。本文中の `$<skill-name>` は `/<skill-name>` と読み替える。
- skill や文書が `AGENTS.md` を参照する場合、リポジトリに `AGENTS.md` があればそれを正本として読む。
